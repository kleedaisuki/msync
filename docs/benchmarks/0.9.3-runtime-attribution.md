# msync 0.9.3 runtime attribution (Linux x64)

2026-11-22. Packaged Native AOT 0.9.3, KVM guest (16 visible vCPUs),
standard scale, seed 17, reference distribution, telemetry off, pinned to one
CPU. This is diagnosis only; no product source was changed.

**Image provenance:** The archived corpus receipts use the local packaged
0.9.3 candidate, which has the same version but distinct bytes from the
promoted GitHub release. See the [HPIR baseline](hpir-0.9.3-baseline.md)
for both image identities and matched comparison instructions.

Extends the [0.9.2 baseline](0.9.2-linux-x64.md), which recorded the signal
source/bound inversion without attributing it.

## 1. Binding inlines a call that disables the whole function's JIT

Same O2 program, same fixture. Only `bind-ir` / `compile --prepare` run
`NativeOptimizer.InlineExecutable`; source and `.mso` runs do not.
P50 ms of five alternating runs after one warmup, exact stdout oracle passed:

| Workload | Image | `.mso` | `.mexe` |
| --- | --- | ---: | ---: |
| signal-hysteresis | release 0.9.3 | 69 | 650 |
| signal-hysteresis | control rebuild | 70 | 724 |
| signal-hysteresis | counterfactual | 68 | 160 |
| polygon-queries | release 0.9.3 | 164 | 378 |
| polygon-queries | control rebuild | 166 | 377 |
| polygon-queries | counterfactual | 175 | 197 |

numeric, live-policy, unicode and B+ are unchanged by the counterfactual
(within window noise). JIT off is 1,337 ms (signal) / 1,072 ms (polygon) from `.mso`.

Chain, with profile-level counters for signal:

1. Binding inlines `draw` into the loop, adding `EnvironmentAddress` and
   `BindLocation` on captured mutable state.
2. Inlining clears `Storage`, so `NativeStoragePlanning` re-plans `<main>` with
   `NativeAddressAnalysis`. Every flagged operand is plain `Top` (no targets):
   `BindLocation %133` and six `AddressOffset`s on Scopes returned by `detector`.
   Re-querying the analysis on the same `AddressOffset`s in the `.mso` also
   answers `Top`, yet their shipped flag is None (see section 1a).
3. `NativeExecutionFunction.PrivateWrites` (`NativeExecutionImage.cs:506-526`)
   returns an all-false vector if *any* instruction is `FrameAlias`.
4. Everything keyed on `RawWritable` is then lost for the function:
   `jit_register_plan_skipped_no_eligible` = 1 (register regions 12 -> 0), and
   `LinkCalls` links no machine calls (`machine_guest_calls` 261,632 -> 0).
   Bridge invocations go from 3 to 327,043; polygon: 229,226 -> 0.

The counterfactual removes only the early return in `TryCollectExposed`.

### 1a. The frame-alias question is not a language question

- `LlvmNativeLowerer` (`LlvmNativeLowerer.cs:128,279`) emits an **empty** storage
  plan. Source and `.mso` runs therefore already use the counterfactual's rule:
  a temporary is private unless it is the target of `FrameAddress`/`BindLocation`
  or marked escaping.
- The language has no address-of, pointer arithmetic or wide frame access, and
  `src/Msync.Hir` contains no `IndexAddress`, `CopyMemory`, `ClearMemory` or
  `RangeFromMemory` emission (only validators, executors and analyses mention them).
  A pointer reaches a frame slot only if lowering emitted `FrameAddress` for it,
  which the `exposed` set already records.
- Real aliases are heap ones: Scope references and captured locations. Those
  matter to memory optimizations (DSE, LICM, EarlyCSE), which use the separate
  `LlvmAliasAnalysis` on LLVM IR.
- `NativeOptimizer.InlineExecutable`, added by 405e7bc7, is the only production
  caller of the Native mid-end. `NativeOptimizer.Optimize`/`PlanStorage` have only
  test callers. `NativeModel` plus `Core/.../Analysis` total 4,928 lines.
- `native-midend-v090.md` describes `NativeStorageFacts` as the replacement; that
  type is not in `src` and never appears in `src` history.

Dropping bind inlining wins 21-90% on five, costs about 11% on live-policy and 7% on

unsafe; that holds only for hand-written IR using wide frame operations, not for
what the compiler emits. The repository test suites were not run on either variant.

installed here), hence the control column. Trees and images:
`.temp/diag-093-counterfactual{,-patched}{,-out}`, `.temp/diag-093-noinline{,-out}`.

## 2. Non-math native calls cost about 1.3-4.8 us each

Loop of 65,000 iterations on an ASCII constant, single statement added,
median of three, microseconds per iteration over the empty loop:

| Body | us |
| --- | ---: |
| `math.floor` twice (JIT direct) | 0.04 |
| string `==` | 0.29 |
| cast to Path | 1.28 |
| `is_ascii` / `utf8_size` / `starts_with` | 1.59 / 1.95 / 2.29 |
| `fs.filename` / `fs.parent_path` | 2.85 / 2.51 |
| `to_lowercase` | 3.77 |
| `path.filename` (stdlib wrapper around `fs.filename`) | 4.78 |

`unicode-path-manifest` performs eight such calls plus casts per row. Summing
the per-call costs gives about 2.0 s of its 2.2 s. Managed allocation is
333 MB (~5.1 KB/row), 39 gen0 collections.

`TierBridge` sends every `CallNative` except unary math to
`CallNative` -> `InvokeNativeDatumAsync` (`NativeInterpreter.NativeCalls.cs:9`)
-> `InvokeNativeAsync` -> `NativeBuiltins.Resolve` -> member string switch:
observed on the code path: argument arrays, async state machines, range/reduction probes and a
`ConcurrentDictionary` lookup by name, on operations that complete
synchronously. The share of each was not isolated: the empty loop stays in machine
code, so these numbers also include the bridge. Candidate: resolve the operation once at link time and add a
synchronous entry for `NativeEffect.Pure` scalar signatures with ready
arguments, as `TryFastUnaryMath` does for `math.*`.

`path::filename` style wrappers add about 1.9 us for a guest call that only forwards.

## 3. Guest calls that are not machine leaves go through managed frames

B+ (2.4 s): 664k calls, 16.7M JIT operations, 2.0M bridge invocations, only
96k machine calls. 250 samples: `TierBridge` 71% inclusive,
`CallDirect`/`RunDirectFunction` 63%, activation entry 13%. Leaf time is flat.
`NativeMachineLeaf.Candidate` rejects any function containing `Call`, any
iterator, or more than 96 instructions, so such functions do not become machine leaves.
Other routes exist (fixed-tier frames, SSA bodies). Per-shape samples and their limits are in
[the XIR audit](../design/executable-machine-ir.md#what-is-measured).

## Not significant

- stdin reads: `RedirectedTextInput` uses StreamReader's default 1 KB buffer
  (2,489 dispatch pauses ~= 2,548,061 B / 1,024). The whole `stdin_lines` loop
  minus an iota loop is <= 61 ms, so the buffer is at most a few percent.
- Compile time: 45-70 ms for core cases; B+ is the exception (~830 ms).

## Limits

gdb timer sampling was used because `perf` is disabled on this host; shares are
approximate. One fixed seed/scale, one machine. A first B+ sampling run stalled
on queued signals and was discarded.
