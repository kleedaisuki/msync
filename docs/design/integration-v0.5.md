## Integration decisions

The structured pipeline owns ordinary CLI/REPL syntax and runtime. Existing IR
command names remain; newly emitted artifacts wrap expanded validated 0.5 object
IR (envelope version 2), never source replay or a saved optimized plan. Contextual
exports freeze local bindings without persisting filesystem proof. Legacy version-1
flat artifacts retain their original read/execute contract rather than silently
receiving the changed literal, destination or barrier semantics.

SSH authentication context must follow actual async tasks and blocking workers;
a thread-local established only at CLI dispatch is insufficient. Owned contexts
remain alive until their work joins, including native credential cancellation.
Packaging retains the per-user installation root, optional owned User PATH,
portable distribution and no recursive removal of user configuration/data.

Publication remains gated on actual successful integrated evidence, not earlier
branch-local logs. The already public v0.4.0 is immutable and will not be replaced.

## Mechanism checks during integration

The first integrated real tests exposed a lifecycle mismatch: independently
valid REPL submissions may consume a port owned by an earlier submission, while
a standalone object must contain its own preceding process launch. Serializing
every REPL submission as a valid standalone object accidentally rejected those
legitimate live-session operations. Exportability is now retained separately as
a result and checked only when export is requested; it cannot gate execution or
prevent live-program context borrowing. Known contextual path captures remain
available after the source file disappears.

The legacy endpoint encoding is also different from structured object encoding.
Version-1 JSON uses externally tagged endpoint variants (`"Local"` etc.), whereas
0.5 objects use a `kind` discriminator. A dedicated serde wire adapter preserves
the legacy format rather than globally changing physical endpoint serialization.
`tests/fixtures/ir-v0.4.0.json` was generated by the publicly downloaded 0.4.0
binary, not by the new serializer.

SSH transport jobs now capture context **before** spawning. Tokio tasks use an
explicit task-local scope and blocking workers use a scoped thread attachment;
JoinSet membership remains unchanged. This follows the ownership semantics of
[Tokio task-local scopes](https://docs.rs/tokio/latest/tokio/task/struct.LocalKey.html#method.scope).
The structured Windows remote-publication client uses the same suspended,
job-enrolled spawn path as other transport clients, preventing helper creation
before process-tree ownership is established.

The actual encrypted-key SSH PTY matrix then exposed two integration-specific
regressions which ordinary tests did not cover: an authentication interrupt
left the structured runtime's cancellation epoch poisoned before `submit` was
entered, and the structured staging owner introduced a writable-cwd requirement
for uploads which previously used absolute source/destination paths. Failed
cancelled authentication now joins/reset the existing runtime epoch. The CLI
keeps workspace `.temp` as its normal scratch root and permits a stable
`MSYNC_STATE_DIR` (default `~/.msync/state`) only for an actual permission-denied
scratch creation. Library callers opt into a fallback explicitly. Recovery
checks both configured roots before effects; non-permission failures never
silently fall back. The read-only fixture overrides state beneath its own repo
workspace rather than writing test data into the user's home.

The integration deliberately retains the branch's crash/restart journeys rather
than claiming unit-test success proves power-loss behavior. The relevant research
baseline is [bounded black-box crash testing (OSDI 2018)](https://www.usenix.org/conference/osdi18/presentation/mohan):
exercise short real effect sequences, inject a failure at meaningful publication
points, restart, and inspect recovered state. This release's process-crash tests
are narrower than device/power-loss crash simulation; existing guarantee limits
remain unchanged.
