# LLVM IR representation port (in progress)

The selected primary representation is LLVM IR with exactly three project
instruction extensions: `HeapAlloc`, `FileIn`, and `FileOut`. These are explicit
operations with typed SSA operands and results, not ordinary runtime calls with
effect summaries. No file-handle instruction family is requested: there are no
new free/open/read/write/seek/close instructions. This does not select the LLVM
backend, libraries or optimization pipeline. Exact inspected source is pinned in
`vendor/llvm-reference/SOURCE.json`; upstream license notices are retained.

Instruction identities from Instruction.def, TypeID identities from Type.h, and
ValueTy identities from Value.h/Value.def are generated by typed development
scripts. The implemented type/value/instruction/module/layout components and
source-aligned transformations are detailed below; their remaining coverage is
explicit. The default public compiler/session callers now use this graph; complete
IR and optimizer coverage remains unfinished. Upstream opcode values are
unchanged; project extensions use the separate 128–130 range and are explicitly
identified as project extensions, not source ports from LLVM.

Managed source translations below must record corresponding upstream files and
methods, C++/C# representation adapters, and incomplete coverage. Unported methods
are not replaced by custom algorithms or declared complete. No new language
capture mode, heap proof, backend or pipeline is inferred from this work.

The real source-to-HIR-to-new-IR producer journey covers ordinary Scope storage,
loops and known file IN/OUT. The new graph now lowers directly to the existing
Native execution format and runs without the old optimizer/address solver;
source-free Native artifact roundtrips run too. Its diagnostic text retains all
three extensions. The default production route is described below; complete
language coverage, remaining IR facilities and the full requested optimization
migration remain unfinished.

| `IR/GlobalValue.h`, `IR/GlobalObject.h` | Constant/User hierarchy, opaque ptr plus value type, linkage/visibility/DLL/TLS/unnamed-address fields, implicit DSO-local update rules; GlobalObject hierarchy only |

Managed representation adapters: the BasicBlock instruction sequence preserves
LLVM intrusive-list complexity through Instruction `Previous`/`Next` links and
block first/last/count fields. Append, insert-before and removal are O(1); the
public instruction view is an enumerable `IReadOnlyCollection`, not an indexed
array. Erasing traversals save the next instruction before unlinking, as LLVM's
early-increment iteration does. Module/function block containers remain private
`List<T>` storage with read-only views in this bounded slice; no constant-time
block deletion claim is made. All containers update parent links and symbols.
`lib/IR/SymbolTableListTraitsImpl.h` supplies the parent/symbol list transitions.
`StringMap` byte keys are represented by a one-to-one hexadecimal dictionary key;
`LlvmValueName.Key` retains the authoritative original bytes. The hexadecimal
form is never an IR name or textual output. C++ assertion preconditions remain
`Debug.Assert`; this is not a new verifier or runtime proof framework.

Coverage is intentionally partial. No context-owned module registration, erase/destructor/BlockAddress lifecycle,
intrinsic ID/signature/attribute subsystem, aliases/IFunc, COMDAT, sections,
metadata, calling-convention/attributes, linking, module flags or serialization
is claimed. `Function.UpdateAfterNameChange` currently covers only the reserved
`llvm.` name bit, not intrinsic recognition. These omissions are not alternative
algorithms. These ownership classes alone establish neither optimization-pass
coverage nor a performance benefit; the current production caller route is
recorded above.

Allocation and file operations belong to the separately implemented explicit
project instructions `HeapAlloc`, `FileIn`, and `FileOut`; they are **not** modeled
here as ordinary external calls. This supersedes the initial ownership task's
ordinary-call proposal. No LLVM backend, pipeline or linked LLVM library is used.
Integration compilation and end-to-end validation are coordinated by the root
agent rather than independently launched from this slice.

Managed adaptations: `LLVMContext`/`LLVMContextImpl` ownership is one partial
`LlvmContext`; arena lifetimes become context-held managed references. Pointer
identity keys remain object reference identities; ordered `ArrayRef` keys become
immutable copied arrays on insertion. Public subtype/parameter views are read-only.
The ordered `SmallSetVector` traversal in `StructType::checkBody` becomes a list
plus a reference-identity set with identical insertion/traversal order. C++
assertion preconditions remain `Debug.Assert`, not runtime validation rules.
`Error`/`Expected<T>` use `TrySetBody`/`TryGet` with an out error string; their
`cantFail` callers use `InvalidOperationException` on the same error path.
The context name-limit option defaults to 1024, exactly the pinned
`lib/IR/IROptions.td` default. Library option registration is not ported.

Snapshot details retained rather than silently repaired: `ByteType::get(1)`
uses ByteTypes rather than the builtin Byte1Ty switch; the global/local structure
target-extension caches share the upstream 64/128 bits; target-extension factory
inserts into context storage before checkParams, so later cached lookup follows
the source path without repeating that check. Direct recursive aggregate subtype
bodies are rejected by this snapshot; opaque pointer fields have no pointee
subtype and do not introduce such recursion. TypedPointerType is represented
separately and remains forbidden in LLVM IR by the upstream contract.

Coverage intentionally stops at the coherent type/context slice needed by
instruction and module representation. APFloat semantics accessors and floating
semantic factories, APInt-valued masks, Value/Constant-index overloads, vector
shape transformation convenience APIs, printing, and C++ destruction are not
ported here. The raw-word IntegerType mask/sign helpers have the same valid
width domain as their upstream C++ shift expressions; no meaning is claimed
for C++ undefined shifts. No custom fallback implements the deferred methods.
This is representation work only: no runtime/compiler execution path, optimization
benefit, allocation/file operation lowering, or telemetry phase is claimed.

C++ interior `Use **Prev` becomes a previous-Use reference plus a linked bit;
the linked head updates its Value's head field. This preserves constant-time
insertion/removal without allocating a separate link cell. `Use::getOperandNo`

Use identities, just as upstream growth invalidates old operand pointers. The
active count setter does not clear dropped references: PHI/Switch/global callers
must first clear the removed operand, matching the upstream ownership protocol.
At this snapshot `ConstantData` values deliberately have no use-list, even though
an operand Use still stores the constant value. String overloads encode UTF-8;
`NameBytes` and `ValueName.Key` retain authoritative byte identity.

Not ported: ValueHandle/TrackingVH and metadata callbacks, BlockAddress ownership
and its RAUW branch, ConstantExpr containment assertion, selective RAUW with
TrackingVH, use-list sorting, materialization, droppable/debug intrinsic helpers,
printing and deletion notification. Those subsystems are absent from the runnable
slice; they are not empty callback implementations. RAUW currently covers values
constructible by this slice, not the unimplemented BlockAddress/metadata cases.
No new verifier, alias state, optimization algorithm or runtime mode is added.
Root coordinates integration compilation and executable representation journeys.

## Instruction foundation and the three project extensions

The instruction slice is translated against the shared reference commit
`a55e64432a516fd6507d3ecfba7407cfe425f940`; it is a representation port, not an
optimizer port or an LLVM backend/pipeline selection. Source mappings:

| Managed file | Upstream source anchors |
| --- | --- |
| `LlvmInstruction.cs` | `IR/Instruction.h`, `lib/IR/Instruction.cpp`: opcode classification, successor replacement, detached cloning and parent removal; `IR/FMF.h`: flag bits |
| `LlvmInstruction.Scalar.cs` | `IR/InstrTypes.h`, `lib/IR/InstrTypes.cpp`: UnaryOperator, BinaryOperator, CastInst, CmpInst; `IR/Instructions.h` and `.cpp`: ICmpInst, FCmpInst, SelectInst, FreezeInst |
| `LlvmInstruction.Memory.cs` | `IR/Instructions.h` and `.cpp`: AllocaInst, LoadInst, StoreInst, GetElementPtrInst; `IR/GEPNoWrapFlags.h`; `Support/AtomicOrdering.h` |
| `LlvmInstruction.Control.cs` | `IR/Instructions.h` and `.cpp`: PHINode, ReturnInst, UncondBrInst, CondBrInst, SwitchInst, UnreachableInst |
| `LlvmInstruction.Call.cs` | `IR/InstrTypes.h` CallBase and `IR/Instructions.h` CallInst: argument/callee operands, function signature, tail-call kind |

Every value operand is an actual `LlvmUse` owned by `LlvmUser`, not a native-slot
integer. Instructions use upstream's `InstructionVal + opcode` subclass ID.
Binary arithmetic retains overflow/exact flags, floating operations retain
fast-math flags, comparison results are scalar/vector i1, and the translated
predicate swapping/inversion tables retain the upstream numeric predicates.
Memory instructions retain opaque pointer address spaces and explicit types,
SSA sizes/indices, alignment, volatile/atomic ordering and synchronization scope.
The shared DataLayout `LlvmAlign` is used rather than a second alignment model.

The exact reference revision matters: branches are separate `UncondBr` and
`CondBr` operations. PHIs have **value-only use operands** plus parallel incoming
block references. Switch operands are **condition, default block, case blocks**;
case `ConstantInt` values live in a separate array, not in operand uses. Removal
in both PHI and switch swaps the last entry into the removed position, clears the
last use, then decreases the active operand count. PHI capacity grows by 1.5x
(minimum two); switch operand capacity triples. Empty PHI deletion replaces users
with the context-uniqued poison value. Call operands are arguments followed by the
callee. Clones create independent use nodes referencing the same operand values,
remain detached and unnamed, and copy implemented operation flags.

Managed ownership replaces C++ ilist allocation/deletion. `BasicBlock` owns
instruction insertion/removal and symbol-table membership. `RemoveFromParent`
detaches without dropping operands; `EraseFromParent` drops operands and destroys
the value name after detaching. A nullable `SourceSpan` attachment is a project
provenance extension, not an operand or LLVM debug metadata; the common clone
wrapper preserves it for all current instructions.

Coverage is deliberately a useful scalar/memory/control/call foundation, not the
entire upstream instruction hierarchy. Missing families include indirect branch,
invoke/callbr and exception handling, vector/aggregate insert/extract/shuffle,
fence, atomic RMW and compare-exchange. The generic managed CastInst currently
represents cast opcodes and flags; individual cast subclasses and full cast
legality/folding utilities are not translated. Metadata/debug locations,
AttributeList, operand bundles, calling-convention enums, branch-weight swapping,
full memory-effect queries and data-layout-derived alloca defaults are not yet
ported. GEP struct indexing currently handles scalar i32 ConstantInt indices;
constant-vector splat struct indices await the corresponding constant-vector
implementation. GEP array/vector indexing accepts integer scalar/vector types.
No missing family is represented by a fake untyped native-slot opcode.

`LlvmInstruction.Extensions.cs` is **project code**, not claimed upstream LLVM:
exactly `HeapAlloc=128`, `FileIn=129`, and `FileOut=130` occupy the documented
extension space. HeapAlloc has integer byte-size SSA operand, alignment attribute,
and opaque-pointer result/address space. FileIn has typed result and source SSA
operand plus Text/Lines/Bytes format. FileOut has typed result and value,
destination SSA operands plus Transfer/WriteText/AppendText/WriteBytes/AppendBytes
mode. Format and mode are attributes, not additional opcodes or an invented file
handle API. The producer selects language Bool for transfer and language Null for
write/append. These classes are inert instruction representations: Lines/Bytes
construction must retain existing deferred language IO behavior; path-to-path
Transfer may consume the path descriptor directly without materializing a FileIn
or forcing buffering. There are no project free/open/read/write/seek/close ops.

## Dead code elimination (DCE)

`src/Msync.Optimization/Llvm/LlvmDeadCodeElimination.cs` translates

## Static natural-loop discovery (pinned stable LoopInfo)

`Msync.Optimization/Llvm/LlvmLoopInfo*.cs` translates static discovery from
`Support/GenericLoopInfoImpl.h` at
`a55e64432a516fd6507d3ecfba7407cfe425f940`, specifically `analyzeImpl`
(lines 469–807), plus the `GenericLoopInfo.h` loop hierarchy/membership carriers
and `getLoopsInPreorder` query. `Analysis/LoopInfo.h` and `lib/Analysis/LoopInfo.cpp`
are accompanying reference sources, not claims that their whole APIs are ported.

This revision **does not use the historical dominator-postorder
`discoverAndMapSubloop` implementation**. Its Stable LoopInfo algorithm is a
forward CFG DFS implementing the header-chain weaving algorithm credited in the
source to Wei et al., “A New Algorithm for Identifying Loops in Decompilation”
(SAS 2007). The translation preserves the actual pinned phases:

1. Visit successors in terminator order, record forward postorder, and weave
   innermost-to-outermost header chains on retreating and off-path edges.
2. Only for reentered/irreducible candidate loops, number the dominator tree and
   reduce candidates innermost-first. Seed with header-dominated predecessors;
   walk backward while collapsing already natural subloops, exclude unreachable
   predecessors, and splice rejected members into the enclosing chain. A header
   with no natural backedge ceases to be a loop.
3. Resolve parents in reverse CFG postorder, count inclusive block lengths in
   postorder, then carve one shared contiguous layout in reverse postorder.
   Each reachable in-loop block is written exactly once at its innermost loop's
   cursor; enclosing loops borrow overlapping slices. Lists are header-first;
   subloops follow program order; top-level loops follow reverse program order.

The public static result exposes `TopLevelLoops`, `GetLoopFor`, `GetLoopDepth`,
`IsLoopHeader`, and forward-program-order `GetLoopsInPreorder`. Each loop exposes
header, parent, children, ordered block slice, depth and containment. Block
containment consults the central innermost-loop map and walks loop parents, as
in the pinned source; there is no separately reconstructed SCC membership set.
The shared `LlvmDominatorTree` provides source-order predecessor traversal from
LLVM Use lists (including duplicate CFG edges), node lookup, dominance and DFS
numbering. Dominance is not a prerequisite global solver for reducible CFGs;
the caller supplies the static tree for irreducible reduction.

Managed adaptations are explicit: the function's existing stable block numbers
index arrays; the array bound is the maximum live block number plus one because
the current Function carrier does not expose the source GraphTraits maximum
number/epoch API. Managed lists replace SmallVector, and ArraySegment exposes
borrowed shared block slices rather than pointer arithmetic. The pending-header
union is a header property plus final slice fields. A declaration yields empty
loop information. These changes do not select a different discovery algorithm,
traversal order, loop parent or membership rule.

Telemetry separates forward DFS, irreducible reduction and contiguous layout;
records reachable/unreachable blocks, CFG edge classes, retreating edges,
header-chain work, reentries, dominated backedges, dominator comparisons,
reverse-edge/enqueue work, unreachable-predecessor exclusions, removed headers,
kept/reparented members, loop counts/depths and layout writes/memberships.
Discovered-loop observations retain function/header identity and source span
when present. Recording-disabled paths allocate neither metric dictionaries nor
per-loop trace attributes and skip telemetry depth walks.

Dynamic insertion/removal, recompute/reuse, block-number epoch updates, LCSSA,
LoopSimplify, loop exits/latches/preheaders utilities, induction/trip-count
analysis, ScalarEvolution, and actual loop transformations are **not** ported
by this static-discovery slice. Reconstruct this result after CFG changes; no
incremental-update facade is supplied. The source algorithm intentionally
reports natural loops, not an SCC partition of every cyclic region. Root owns
serialized compilation and focused CFG property validation; this worker did
not launch an independent build or select an LLVM backend/pipeline.

## Source builtin representations and explicit conversions

`LlvmHirLowerer.Types.cs` / `.Conversions.cs` define project source-language
representation choices, not LLVM optimizer algorithms. Their contracts come from
`language-v080.md` (explicit conversion table), `HirType` / `HirLocation`,
existing `NativeHirLowerer.Conversion` and `NativeImage.Convert` execution.

| Source value | LLVM carrier |
| --- | --- |
| Null | Empty structure |
| Never | Empty no-value carrier; reachable values are not introduced |
| Bool / Number | i1 / double |
| String, Range, Scope, Connection, Process, Type | Ordinary pointer to the corresponding runtime object/allocation |
| Path | Existing two i8 fields and five typed pointer roots |

The union raw scalar capacity is i64 if Number occurs, otherwise i16 if Path
occurs, otherwise i8 if Bool occurs, otherwise an empty byte array. Pointer root
capacity is five if Path occurs, otherwise three if Function occurs, otherwise
one for an ordinary pointer builtin, otherwise zero. Standard LLVM DataLayout
places/aligned these fields. Discriminator cases correspond to the existing
`NativeKind` cases; inactive payload capacity is not a separate managed object.
This describes source LLVM values, not the external Native2 encoding. Native2
retains its existing one-byte tag/max-raw/max-root storage (including its existing
Function and namespace-address payloads). The target adapter moves these values
through the existing slot encoder rather than changing artifacts or pretending
the two layouts have identical byte offsets. Native `Copy.Type`, when present,
means a shared physical format for both source and destination, not the
destination logical type. Carrier adaptation must use the untyped Copy path,
which obtains both slot representations and moves the actual case payload.
Treating a mono Number source as a destination nullable-union format reads
payload bits as a discriminator; the nullable-return journey exposed exactly
that failure (expected 8, observed 0 from an incorrectly Null result).

`Represent` is a typed ordinary ABI binding for static tag packing/payload
extraction; the current Native2 target emits `Copy`. Equal LLVM carriers require
no representation operation, even when source logical metadata indices differ.
There is no `Narrow`, per-reference admission, layout validator, universal object
box, alias solver or extra IR opcode. These binding declarations preserve source
union structure in SSA instead of erasing every union to an opaque object.
They are currently target ABI operations, not source LLVM scalar bit packing
instruction sequences.

Actual HIR `Convert` is a separate typed binding to existing `NativeOp.Convert`
with its explicit flag set. Identity/widening `Coerce` only changes
representation; representation-changing implicit coercion retains the existing
conversion behavior, including String/Path contextual conversion. Explicit

existing runtime conversion primitive, not a new HIR evaluator. `IsNull` and
`IsType` (including dynamic Type operands) use existing scalar primitives.
Source `TypeOf`/`decltype` denotes the child's static type without evaluating
the child, and lowers through the same literal relocation as `TypeValue`;
the separate runtime ValueType binding is not source decltype execution. Connection and Type literals
use existing `NativeConstant` construction and runtime resource binding.

including `AdmitsNull`, then explicitly extract/repack the flow-refined result.

integer interval dependency is the separately translated `LlvmConstantRange`,
not the source language Range object. Integer values are not forced to
Overdefined to avoid implementing this dependency. Raw floating-point constants
retain their context-uniqued APFloat bit identity, so +0/-0 and NaN distinctions

The wrapper intentionally does not claim the unported post-range

non-library-foldable path. Project HeapAlloc/FileIn/FileOut instructions are not

instructions accepted by the shared DCE predicate. Unreachable code can be
removed, including effects which cannot execute.

in their component notes. Nonzero symbolic GEP constants and the absent LLVM
intrinsic/TLI families are not approximated with invented evaluators. Flat
structure constants are supplied by the separately translated ConstantStruct

reconstruct it after a CFG change. No fake DomTreeUpdater or preserved-analysis

spans. LLVM constants remain context-uniqued and are not stamped with a replaced

SCCP replacement, and cases such as unsigned-min of an unknown value and zero

### Address views after ordinary LLVM pointer simplification

blocks, avoiding an unnecessary dominance analysis. Ordinary operand consumption

### PHITransAddr: non-inserting predecessor-edge address translation

The source port follows `Analysis/PHITransAddr.h` and
`lib/Analysis/PHITransAddr.cpp` at the pinned LLVM commit. Both files are retained
under `vendor/llvm-reference/llvm/`. The non-inserting translator owns an address

not a global equation solver, alias-identity constraint, or allocation proof.

`isPotentiallyPHITranslatable`, `translateSubExpr`, `RemoveInstInputs`, both
non-inserting `translateValue` overloads, and `getSelect`. Translation substitutes
the PHI incoming value for the actual predecessor edge. Changed casts and GEPs

the predecessor. Add translation combines constant immediates, clears the source
nowrap flags after reassociation, simplifies, and otherwise finds an existing
add. The translator never inserts an instruction. The source's user-list scan
restrictions for constants/ConstantData and same-function GEP/add candidates are
retained, as is the final `MustDominate` block check.

information. Select-dependent translation works on two independent copies of the
expression state, folding a matching incoming select to the requested side.

source, even for a non-instruction address; the implementation retains that
behavior. The release-path translator does not add the source's debug-only
recursive consistency checker to compiler workloads. Inserting translation is
outside this consumer's scope and is not claimed.

as the upstream methods require. Reallocation copies only that loop's block

original layout. Subsequent private edits preserve source order and capacity

previous view still references them. Header is the first block, without a
per-query construction-state branch; PendingHeader is used only internally by
static discovery until the layout carve completes, as in the upstream union.

querying Header. `AddBlockEntry` changes only the raw block list, while
`AddBasicBlockToLoop` changes the innermost map and appends to that loop and each
ancestor. `RemoveBlockFromLoop` changes only the block list, and `RemoveBlock`
removes a block through its map-selected ancestor chain and clears the map.
`ChangeLoopFor`, `ReplaceLoop`, child detach/attach and top-level detach/attach
retain these separate source responsibilities; none silently rebuilds or
"repairs" other data structures. This is important during temporary hierarchy
restructuring: Contains(BB) uses the map/parent chain and callers that are still
building raw membership must use Blocks, exactly as the source documents.
Block numbers are currently monotonic in the represented Function; map growth
uses that function's next block number. Renumbering/epoch-changing APIs are not
represented or simulated with a fake epoch.

case clears direct mappings and promotes children in source order. Nested erase
runs the real UnloopUpdater: streaming postorder traversal propagates nearest
reachable ancestors, records direct-subloop exit parents, detects irreducible
backedges and repeats over cached postorder until the source fixed point, removes
members from former ancestors and reparents direct children. Traversal finishes
postorder **after** yielding the block to the updater, preserving the interaction
with changing block-to-loop mappings and the source hasPostorder assertion.

can still be compared, mirroring the source allocator's retained-but-invalid loop
identity. No custom dominator or loop-discovery algorithm substitutes for erase.

repeated edges from one outside predecessor; GetLoopPreheader additionally
requires one successor edge and source legal-hoist termination. GetLoopLatch and
GetNumBackEdges count predecessor edges rather than deduplicating blocks. Exit
blocks preserve repeated edges, unique exits explicitly deduplicate, and exiting
blocks appear once per member block. Source LCSSA-form APIs interpret PHI uses
on incoming predecessor edges, ignore unreachable uses and optionally ignore
token-like values. They are available for upstream Debug.Assert contracts, not
installed as an unconditional production validation gate.

## LCSSA formation

`LlvmLcssa.cs` and `LlvmLcssa.Form.cs` translate the formation algorithm in
`llvm/lib/Transforms/Utils/LCSSA.cpp` at
`a55e64432a516fd6507d3ecfba7407cfe425f940`. Public entries are the function-wide
`Run(function, DT, LI, trace)` and source-shaped `FormLCSSA`,
`FormLCSSARecursively`, and `FormLCSSAForInstructions` helpers. The independent
SSAUpdater source port supplies the actual multi-exit SSA reconstruction; no
custom recursive-PHI or single-exit-only replacement is substituted.

The loop traversal is inner-first. Formation caches exit-edge blocks and walks
immediate dominators upward from exits to identify blocks that can define live-
out values. It skips subloop blocks already processed, unused definitions,
single non-PHI same-block users, and token-like types before scanning uses.
`GenericLoopInfoImpl.h::getExitBlocks` preserves duplicate exit edges; the exit
PHI insertion map, not a changed exit-set contract, handles duplicates.

Uses of PHIs are interpreted on their incoming predecessor edges. Unreachable
user blocks receive poison as in the source. For each actual live-out value,
LCSSA inserts PHIs only in dominated exits, copies every incoming edge, records
outside-loop predecessor uses for rewriting, and makes those exit definitions
available to SSAUpdater. Source fast paths remain: uses located in exit blocks
refer to the new first PHI, and a sole added exit PHI directly renames all uses.
Otherwise the shared SSAUpdater performs the real PHI-placement/reconstruction
algorithm. Newly inserted PHIs in disjoint loops are requeued for LCSSA closure,
and unused added exit PHIs are removed (or returned to an explicit caller-
owned cleanup list) after the complete worklist finishes. Early-increment
intrusive-use traversal preserves the original source behavior while rewriting
unreachable uses. The source's Changed return is retained, including that its
unreachable-use poison rewrite alone does not set Changed; the actual rewrite
is nevertheless counted by telemetry.

Formation never changes CFG edges or basic-block ownership. Existing static
DominatorTree/LoopInfo therefore remain genuinely valid through this pass;
there is no fabricated preserved-analysis declaration or no-op analysis updater.
LoopSimplify's CFG changes must be followed by its actual DT/LoopInfo mutation
mechanisms (or real reconstruction at a caller-owned boundary) before those
analyses are passed to LCSSA. No LoopSimplify-form validation gate is added:
the source disjoint-loop postprocessing is retained rather than rejecting the
represented CFG case.

The source ScalarEvolution hooks execute only when an SE instance is supplied;
this IR implements the source null-SE path. LLVM debug records and lifetime
intrinsic identities are outside this formation slice, so their specialized
rewriting/removal branches are not claimed. Ordinary calls are not classified
as lifetime intrinsics by name. Diagnostic SourceSpan is copied to new exit
PHIs (the project analogue of the source debug location), not passed off as a
complete LLVM debug-metadata port. Existing project LogicalType and per-use
LogicalType carriers are preserved explicitly, including through SSAUpdater's
optional carrier parameter, so inserted definitions retain the Native target's
established ABI representation. No resource-lifetime or heap-alias analysis is
introduced.

Detailed sink-neutral telemetry includes the pass, loop/nest or explicit-
instruction entry, dominate-exit walk, candidate scan and per-live-out rewrite
spans. It records exit/predecessor cache work, CFG edge visits, domination skips,
definition/use counts, unreachable poisoning, duplicate exits, inserted/removed
PHIs, direct versus SSAUpdater rewrites and disjoint-loop worklist entries;
SSAUpdater contributes its real solver work to the same caller context. Live-out
spans carry function/block/instruction/source provenance. Disabled recording
avoids telemetry dictionaries, source formatting and per-value closure capture.
Expensive source verification/pass-manager plumbing is not turned into a new
product gate. Root owns the coordinated incremental build and loop journeys;
this owner did not run an independent build.

## SSAUpdater: local-definition solver and PHI graph reuse

`LlvmSsaUpdater.cs`, `.Solver.cs`, and `.Phis.cs` translate pinned

`a55e64432a516fd6507d3ecfba7407cfe425f940`. The implementation is the actual source
local-definition solver, not recursive provisional-PHI construction:

* Search backward to available definitions, caching predecessors. If present,
  the first IR PHI supplies predecessor order; otherwise use source CFG order.

  Queries unreachable from definitions return poison.
* Build subset immediate dominators using the source Cooper–Harvey–Kennedy

  full-function dominators: available definitions are roots. Unreachable

  singular values, match existing PHI graphs with tags/cleanup, create empty PHIs
  only where needed, and fill them in reverse worklist order.

### HeapAlloc successful-result semantic adapter

The existing first-class `HeapAlloc` opcode now has an explicit contract: on
successful completion it produces fresh non-null writable storage of its integer
SSA `ByteSize` operand, with its `Alignment`. Bytes are uninitialized. There is
no HeapFree, user allocator/free or FFI operation in the represented IR; host GC
does not invalidate live references. Consequently live allocation results remain
valid for their uses. This is a language/extension fact supplied by the producer,
not an inferred noalias-call attribute or an additional lifetime proof.

The adapter feeds existing source algorithms rather than adding a heap analysis:

- BasicAA identifies allocation objects, function-local fresh results and base
  pointers; distinct allocations and pre-existing arguments follow the existing
  local source disambiguation paths.
- ObjectSize reads a constant ByteSize directly (including the existing
  round-to-alignment option). It does not recover size from LogicalLayout or add
  an unknown-allocation solver. Current ordinary object producers emit known
  DataLayout byte counts. Dereferenceability uses that actual extent, and known
  pointer alignment/nonzero/defined-result queries use the declared facts.
- The allocation itself remains non-speculatable, so its byte facts do not need
  an execution-context/temporal validation gate. Like alloca, it cannot be
  speculated to manufacture a pointer before execution. No represented operation
  frees a live allocation, so these facts require no willNotFreeBetween scan.
- LICM uses writable storage directly. Unwind invisibility follows the upstream
  fresh-noalias-result rule and still requires no capture before/in the loop;
  unlike alloca it is not unconditionally treated as disappearing on unwind.
  Thread-local classification uses the existing source capture query.

Allocation reads/writes allocator bookkeeping in **InaccessibleMem**, not bytes
of an ordinary pre-existing MemoryLocation. AA therefore returns NoModRef for
those concrete accessible-location queries, while locationless allocation
queries retain ModRef. Uninitialized newly returned bytes are not an implicit
initialization store. Core may-read, may-write and may-throw behavior is unchanged;
HeapAlloc is not made speculatable, CSE-eligible or movable, and every execution
still has fresh identity. FileIn/FileOut effects and all ordinary call contracts
are unchanged. No SourcePrivateTrace marker or optimization/execution gate is
required to use these facts.

`HeapAllocationFactsProperties.Run()` exercises actual field GEPs, distinct
objects, argument separation, ByteSize/Alignment, defined non-null pointers,
writable/unwind/capture facts, allocator-state versus field ModRef, and the
unchanged non-speculation contract. Optional metrics identify each adapter route
and concrete unknown-size outcome. LICM's real SourceScope promotion journey is
validated by the coordinator; no independent build is launched for the adapter.

instruction selection, not delayed runtime evaluation or a language thunk.
Native temporaries are emitted at each use, so no cross-block cache or new
dominance analysis is needed. The ordinary structured `{0, field}` fast path
retains direct O(1) selection.

Field lookup tables are built once per declared LLVM structure and use O(1)
(offset, native payload type)/(offset, LLVM payload type) queries. The payload
view matters for zero-sized LLVM fields: `{ {}, double }` places both fields at
LLVM byte offset zero, while Native's existing field-address representation can
place their storage cells differently. A known consuming view selects the actual
declared field rather than blindly treating every zero offset as a Native base
address. Raw zero-offset object pointers still alias the existing root. Existing
per-use ABI annotations and declared load/store payloads supply these views;
shared constants are not retyped and no alias-identity constraint is introduced.
Session cells, relocated literal loads and singleton flag/address relocation keep
their existing Native resource contracts.

The remaining boundary is explicit: dynamic integer-index carriers, scalable
strides, repeated-object arrays outside the represented allocation contract,
interior accesses to compact builtin descriptor bytes, and opaque roots without
a declared storage layout are not a general pointer backend. No iN index is
pretended to be a Number, no HIR is reconstructed, and no runtime heap/layout
proof is added to bridge those gaps. Diagnostics identify the unsupported GEP
and its source context.

Function telemetry records constant relocation expressions, materializations and
raw zero-offset aliases. `PointerArithmeticJourney.RunAsync` replaces real
producer GEPs using the actual default IRBuilder, then executes Number,
Function/Scope-reference, zero-sized-prefix and aliasing journeys through the
Native target and detached Native2 artifacts. It also uses the builder's actual
constant array-stride form. The integrated `--simplify-cfg-only` run completed
with zero build warnings/errors and **all 19 pointer executions passed**. The
zero-sized-prefix fixture uses the existing nullable-field syntax `empty?: null`;
no language rule was changed to make the fixture pass.
Two of these executions lower the same graph twice with a newly declared Bool
cell whose pointer carrier does not exist in the input type table. The test
requires all source definition/use annotations to remain unchanged, ensuring
target-private type IDs stay in Body-local slots/views rather than leaking back
into the reusable LLVM graph.
The observed repeated-lowering executions and unchanged-annotation assertions

### Speculation cache fixture: integer division is intentionally not the consumer

The pinned `ValueTracking.cpp` lines 7874–7882 accept a speculative unsigned
divide/remainder only when its divisor is a nonzero constant APInt. This switch
does **not** consult nonzero assumption facts. A cached `assume(denominator != 0)`
can therefore prove `isKnownNonZero` without making that variable division
speculatable. The earlier SimplifyCFG fixture incorrectly expected that extra
permission; production follows the source and was not broadened.

The corrected fixture checks that distinction directly. Its positive end-to-end
cache-consumption case is instead a conditional load through a pointer argument
with actual retained `dereferenceable` and `align` bundles. Unlike the integer
divide cases, the source load arm passes its SimplifyQuery/AC into
`isDereferenceableAndAlignedPointer`. The no-cache form must retain the load in
its conditional block, and the cached form may hoist it subject to the unchanged
TTI cost gate. This exercises the actual supported consumer rather than lowering
a budget or inventing additional speculation rules to satisfy a fixture.
