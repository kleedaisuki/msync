# msync 0.5.2

## Compile-time language additions

- `symbol name(parameters): ... return value` inlines pure generic computation.
  Parameters can be items, strings, spaces or existing program capabilities.
  Independent lexical scope and explicit `global` retain prior definitions;
  invalid type deductions are diagnosed when instantiated with owned source
  definitions, argument locations and call ancestry. A terminal return is required.
- Use `release`, `acquire`, and combined `acqrel`. Scheduling semantics are
  unchanged; `async`/`await` are still accepted compatibility aliases. Formatting
  emits canonical new source words. Internal object scheduling operations remain
  compatible.
- `execute path_or_filename` expands source with a fresh lexical environment per
  matched file. `include` expands it into the caller environment. Neither adds
  blocks or runtime script operations. Selector matches execute in Unicode
  lexicographic order, not filesystem enumeration order.

Source directives currently read ordinary compiler-local files. Relative source
filenames resolve from the containing script; unnamed input uses caller cwd.
Explicit environment-space source paths use cwd for relative environment values,
matching their object relocation semantics.
Ordinary child data paths keep caller cwd; `$file` tracks the actual child source.
Source files must already exist when compilation begins, not be generated by a
preceding runtime statement. Input cycles/streams and excessive expansion are
rejected before runtime effects. Do not treat a filename string as inline code.

## Reusable objects

Expanded code runs without the source scripts. Explicit feature-tagged source
module metadata preserves child/captured `$file` contexts and relocation;
caller-provided module bindings override defaults. Debug filenames are not
semantic link inputs. Older objects remain supported; older readers must reject
new source-module features rather than misinterpret them.

## Installation and limits

Per-user Windows setup, portable ZIP, Linux archive, PATH ownership, user-data
retention and native SSH authentication behavior are unchanged. Windows packages
remain unsigned. Obtain a published asset only from the matching official GitHub
Release and verify its SHA256SUMS; this document alone does not certify a release.

See [language definitions](../design/language-v4.md) for source lookup,
constant-evaluation/source-expansion bounds and namespace/item distinctions.

## Candidate validation

Incremental Linux acceptance exercises real CLI and REPL compilation, generic
symbol calls, canonical scheduling controls, deterministic source selection,
and object/structured-IR execution after deleting source files. Targeted source
binding regressions cover cwd-relative environment values and mixed relative /
absolute inclusion followed by moved-object execution. The finite-source FIFO
probe runs in a killable subprocess so a blocking regression cannot hang the
test harness. These are local candidate results, not a claim that Windows
packaging or publication has completed.
