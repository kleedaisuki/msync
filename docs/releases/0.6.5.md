# msync 0.6.5

**Locally accepted; unreleased.** The integrated 0.6.5 implementation has passed
local functional, compatibility and real-editor-host acceptance, with bounded
performance costs retained explicitly. Native package, Windows installer and
editor workflows passed on the development branch with publication skipped;
the final native Ubuntu/Windows Rust revalidation also passed. The
[integration workboard](../design/integration-v065.md) owns the
requirement/evidence map. This document neither publishes a release nor changes
any previously published tag or asset.

## Inferred types and operator capabilities

The compiler's semantic model explicitly represents `Path`, `String`, `Scope`,
`Bool` and `Range<T>`, alongside program/port values. Source remains inferred:
there is no new type-annotation or user-defined trait-declaration syntax.
Operators use common operand/result capabilities rather than spelling-specific
function patterns.

| Operation | Accepted operands | Result |
| --- | --- | --- |
| `/` | Each side is `String` or `Path` | `Path` |
| `::` | `Scope` with `String` or `Path` | `Path` |
| `::` | `Scope` with `Scope` | `Scope` |
| `and`, `or`, `not` | `Bool` | `Bool` |
| `==`, `!=` | Matching `Bool` or matching `String` | `Bool` |
| `<`, `<=`, `>`, `>=` | `String` with `String` | `Bool` |

Value constraints still apply after type checking: rooted right-hand joins,
incompatible endpoints and invalid namespace members do not become implicit
conversions. A bare quoted value remains String data; qualification or joining
can give it explicit Path meaning.

`$` denotes built-in scopes/APIs. Function calls return ordinary inferred values,
so scope qualification composes with lexical functions and nested scopes:

```text
symbol codex(file):
    return ~/.codex/file

config := $wsl::codex(config.toml)
```

This is a WSL-scoped path returned by `codex`, not a remote executable invocation.
Home and relative components must not be resolved against the local host before
the selected scope is applied. A renamed function or a Scope-returning function
uses the same rules. Scope composition applies the inner scope and then the outer
scope, preserving captured contexts; conflicting explicit physical endpoints are
errors rather than arbitrary reinterpretation. The shared [type contract](../design/type-system-v065.md)
defines this boundary; public acceptance distinguishes pure WSL binding from an
actual WSL transport session.

## Built-in range APIs and ordered literals

`$view::NAME` is the canonical namespace for range constructors, adaptors and
scalar consumers. Existing working `views::` and `ranges::` spellings remain
compatibility aliases. Ordinary user functions named `single`, `filter`, etc.
retain their lexical meaning outside their established built-in positions.
The built-in API is itself a typed Scope: `api => $view` allows a pipeline such as
`items | api::take(1)`, rather than reserving only the literal spelling `$view`.

```text
boolean flip(flag):
    return not flag

for flag in [true, false, flip(false)] | $view::transform(flip):
    if flag:
        "enabled" -> selected.txt

files := [$pwd::"input file.txt", input.txt]
(files | $view::front) -> first.txt
```

Literal ranges preserve insertion order. Elements may be String data, Bool values
or scoped/default-local Paths, including expanded symbol/boolean calls. Mixed
allowed members infer a finite scalar union; an operation on the item must be
valid for every possible type. An argument-independent projection can turn a
mixed range into a String range, but a `String | Bool` item is not itself a valid
condition. Nested ranges, Scope values and ports are not scalar elements.

Regex selectors remain lazy Path ranges with deterministic directory-entry
ordering. Filters, projections and short-circuit consumers perform only demanded
work; `take(0)` does not enumerate its source. Bool elements are valid in literal
ranges and suitable typed views, but Bool or non-Path mixed ranges do not silently
become file-transfer operands.

## Scheduled conditionals

```text
if release exists input.txt:
    input.txt -> output.txt
else:
    "missing" -> output.txt
```

`if release`, `if acquire` and `if acqrel` apply the established release/acquire
flags to the conditional, including its alternative branch. The condition must
still have Bool type. These forms do not add a global join of an unrelated
released flow or external program. Actual held-work order, not only parse output,
is part of [independent acceptance](../design/validation-v065.md).

## Historical correctness repairs

- **Executable public compiler API:** recursively contextualize typed control
  operands before returning an executable program. Portable compilation remains
  relocatable, and a binding failure must not commit compiler-session state.
- **Finite implicit range transfer:** `range -> container/` remains one
  recoverable file-publication statement. A later selected-target collision must
  not leave an earlier member published. An explicit `for` is still a sequence of
  statements, not a whole-loop transaction.
- **Empty executable recovery:** empty source, declarations, folded branches,
  objects and IR must not skip abandoned statement state. Retained sessions use
  their own recovery roots, notice later orphaned state and preserve live owner
  locks. Missing unused roots keep the no-storage cold path.
- **Source-owned diagnostics:** inferred operand and composed-member failures
  retain their original source/provenance rather than becoming unrelated source
  errors or borrowing the first line of the script.
- **Windows resource identity:** canonicalize known verbatim/ordinary drive and
  UNC roots for logical resource comparison, preserving the original IO operand
  paths. A 64-case alias/sibling property and 512-case index oracle guard both
  true alias recognition and independent-resource separation. This repairs
  false global joins and missed aliases without guessing filesystem equality
  from unrelated path spellings.
- **Portable timestamp fixtures:** Windows `SystemTime` represents 100ns
  intervals, so constructing `UNIX_EPOCH + 123456789ns` already yields
  `123456700ns` before the formatter sees it. The portable test uses that exactly
  representable value; Unix retains the exact `123456789ns` case and signed
  pre-epoch checks. This fixture correction does not reduce transfer precision
  or change production timestamp formatting. The
  [metadata record](../design/ssh-performance-v065-metadata.md#native-systemtime-fixture-precision)
  distinguishes it from the real fractional-transfer repair.
- **Prompt completion:** eliminate the real REPL Ctrl-C/drain notification
  deadlock. The input reader can leave its loop before a completion sender uses
  the external printer; a blocking single-slot queue could then wait forever
  without a consumer. The maintained Rustyline 19 correction keeps ordered
  messages and native rendering with nonblocking/coalesced wakeups. It adds no
  notification thread, test sleep or timeout workaround. Ordered delivery keeps
  each raw-mode message's implicit newline, while non-raw direct writes preserve
  their bytes. Deterministic departed-reader, saturated-pipe and stale-wake cases
  complement the actual PTY journey; the Windows event/queue counterpart is
  maintained separately from Unix transport evidence. The
  [lifecycle record](../design/runtime-activity-v6.md#editor-reader-completion-and-notice-backpressure)
  and [dependency provenance/patch](../../vendor/rustyline/README.msync.md) retain
  the actual PTY reproduction, narrow source changes, upstream identity and
  original license.

These repairs reuse the existing statement-local publication/recovery owners;
they do not introduce a database, daemon, global transaction manager or manual
recovery ritual. See the [historical inventory](../design/history-v065.md) and
[publication contract](../design/statement-atomicity.md) for reproductions and
accepted ownership boundaries.

The range-publication repair applies when source is compiled to the new typed
`RangeTransfer` operation. A legacy object may already encode an implicit selector
as an ordinary `For`, indistinguishable from an explicit user loop without
guessing from debug source. Those existing `For` opcodes retain their established
per-iteration semantics; they are not retroactively reinterpreted as atomic
cohorts. Recompile the original selector source to replace those old objects with
the corrected cohort operation. Preserving the old bytecode contract is
separate from correcting new source compilation.

## Compatibility, editor and delivery

The default source grammar retains its 0.6 name and compatible established aliases.
The older persisted control spelling `Space` remains a wire name for semantic
Scope, not a second source type. Existing objects retain their interpretation
contract; new typed constructs require feature negotiation rather than silently
changing an old instruction's meaning.

| Object feature | Compatibility contract |
| --- | --- |
| `typed_control_v1` | Existing typed control-flow meaning and legacy scalar encodings remain supported |
| `source_modules_v1` | Existing source-module and captured-context meaning remains supported |
| `typed_values_v2` | Required for Bool/union ranges, composed or API Scope values, Scope-valued selection, typed path conversion and implicit single-cohort Range transfer |

`typed_values_v2` is emitted only when required; feature detection and validation
inspect exported values as well as code. The normalized finite-union wire remains
human-readable even when the compiler's internal type layout is compact. A reader
that does not support a required feature must reject it, not silently reinterpret
the operation. The object format version is not a promise that an older reader
understands these new semantics.

The editor package follows version 0.6.5 and uses the same language frontend for
diagnostics, formatting and semantic services. The actual VS Code 1.144.0 host
passed all nine phases against the refreshed delivery executable: activation,
diagnostic repair, formatting, canonical/aliased API completion, qualified symbol
navigation, UTF-16 semantic tokens and no DSL effects. This is automated Xvfb
editor-host acceptance, not a human visual assessment or marketplace publication.
