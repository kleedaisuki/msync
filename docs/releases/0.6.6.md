# msync 0.6.6

This release replaces transaction-oriented synchronization with ordinary copying
and retry, and removes the normal-path costs of persistent recovery machinery.
The source grammar remains 0.6, with the existing 0.5 compatibility alias.

## Changed transfer contract

- An ordinary local file uses a same-directory temporary file, at most one file
  fsync, and native atomic replacement. No filesystem-wide syncfs, before-image,
  commit journal, parent-wide publication lock or startup recovery scan.
- Directory containers merge selected entries and overwrite same-name files,
  retaining unrelated children. Explicit `/.` still replaces the selected tree.
- **Failed multi-file work may leave completed members in place. Retry the
  transfer.** This deliberately supersedes the earlier rollback/recovery promise.
  Legacy state is left untouched and is not required for new work.
- Preserve native linked workspaces, recursive symlink entries, exact supported
  timestamps, executable modes and normal pathname characters. The kernel
  decides actual permissions instead of broad policy-based refusals.

## One native SSH channel

A finite transfer carries discovery, metadata, bytes and completion through one
native SSH exec per selected endpoint, without SCP/helper reconnects, implicit
preauthentication or commit-receipt queries. OpenSSH still owns aliases, config,
agents, proxies and authentication prompts. Bare static remote regex transfers
are batched rather than authenticating once per selected file.

The client encodes/decodes tar in Rust; Windows needs no external tar executable.
The POSIX remote host needs GNU tar and GNU cp/mv. Physical FIFO/socket transfer
helpers additionally use remote Python 3; ordinary file transfers do not.

## Compiler, runtime and tooling

- Build compact execution dependency graphs instead of retaining a proof for
  every independent instruction pair; keep the public detailed explanation API.
- Avoid repeated validation of internally owned, already-decoded objects. Remove
  arbitrary source/import/object/query/document size and width caps while
  retaining actual language, wire-format and native stack constraints.
- Retain native file descriptors for selected released inputs, support FIFO
  participant groups and queue independent flows without blocking the REPL.
- Separate optional telemetry failures from transfer outcomes, and use
  nonblocking SQLite ingestion with observable dropped-event counts.
- Accept ordinary editor input, large LSP documents, and formatting through
  selected symlink targets. Remove inactive-configuration execution gates.

## Verification and scope

Local focused property tests, actual CLI journeys, Linux strict static checks
and Windows-target cross checks passed before publication preparation. Real
OpenSSH acceptance covers 12 upload/download/overwrite/cohort/link/name/failure/
retry journeys, each using one SSH client, zero SCP clients, one authentication
and one remote exec. Additional real-process checks cover a 2,200-file selector
and cancellation without surviving owned remote helpers. Local file syscall
checks observed one fsync and zero syncfs for new and overwritten targets.

These loopback Linux measurements are not a claim that the originally reported
35-second Windows/VPN transfer has been timed on that machine. Native package,
installer upgrade/repair/uninstall, and real VS Code host acceptance are run by
the release workflow against the packaged binaries, independently of unrelated
CI checks.

See the [current transfer contract](../design/statement-atomicity.md),
[reproducible validation](../design/normal-user-validation.md), and
[cost audit](../design/safety-cost-audit.md). Historical v0.6.5 tags, assets and
measurements remain unchanged.
