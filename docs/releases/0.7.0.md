# msync 0.7.0

This release introduces a source-backed standard library, explicit lexical
namespaces and Scope ranges for reusable endpoint-distribution scripts.
Syntax 0.7 is canonical; existing 0.5/0.6 source remains accepted.

## Standard facilities

```text
fs => $std::fs
views => $std::ranges

scope hello:
    codex := ~/.codex

remote => ssh://forge
if fs::is_directory(hello::codex):
    hello::codex -> remote::backup/
```

- `$std::fs` provides runtime file/directory/link predicates, status,
  directory traversal, creation/removal, normal-copy operations, rename and
  links, symbolic permissions, resolution and lexical path manipulation.
- `$std::ranges` groups lazy range construction, adaptation and consumption.
  `$view`, `views::` and `ranges::` remain compatible.
- `$std::path`, `$std::bool` and `$std::string` provide typed composition,
  boolean expressions and Unicode text primitives.
- Source-defined functions use the same lexical specialization as user code.
  Host facilities have explicit `native` declarations and typed scalar/Range
  results or `Void` statements. Return annotations may be inferred from the
  registered capability; dependent range primitives specialize callbacks into
  the existing typed lazy IR. Native identifiers are registered msync
  capabilities, not executable shell text.

See the [filesystem inventory](../design/filesystem-v070.md) for individual
operations, return values and platform semantics. Numeric sizes/counts, clocks,
storage-space records and process-global cwd mutation are not introduced by
this release. Filesystem status is a finite string-tag domain; permission bits
have symbolic string names. Quantities are not disguised as strings.

## Namespace and endpoint composition

`scope name:` declares a lexical namespace; `name::member` selects its declared
member. Namespace aliases use ordinary inferred Scope values. Nested scopes,
functions and macros preserve lexical ownership instead of leaking members into
the parent environment.

```text
forge => ssh://forge
myvpn => ssh://myvpn
wsl => $wsl

macro copy_to(scope, file):
    $local::file -> scope::file

for file in [~/.codex/AGENTS, ~/.codex/codex.prompt]:
    for scope in [wsl, myvpn, forge]:
        copy_to(scope, file)
```

Scope ranges preserve ordering and endpoint identity through ordinary typed
adaptors and consumers. Unbound range Path values retain their source spelling
and a local projection: a later selected endpoint resolves its own home, while
explicitly contextualized paths cannot silently change endpoints.

## Runtime and compatibility

Filesystem observations happen at runtime, including in source-free objects and
IR. Checking, planning, compilation and dry-run do not execute native filesystem
effects or authenticate unused endpoints. Native argument paths participate in
normal execution dependency ordering; lazy range sources are not observed until
demanded.

The new `native_std_v1` object feature covers native calls, lexical namespaces
and deferred path provenance. Historical 0.5/0.6 object semantics remain accepted.
The regular-file same-directory staging, atomic replacement and ordinary
multi-file retry model are unchanged. Completed members remain visible after a
later failure; no rollback journal or recovery registry is added.

## Editor and packages

VS Code provides namespace-aware completion, hover, call signatures and
definition jumps into the same embedded standard-library sources used by the
compiler. Read-only virtual source documents work without a repository checkout
or a writable cache. Portable packages additionally include `share/msync/std`.

Release assets:

- `msync-0.7.0-windows-x86_64-setup.exe`: per-user Windows x64 installer.
- `msync-0.7.0-windows-x86_64.zip`: portable Windows x64 package.
- `msync-0.7.0-linux-x86_64.tar.gz`: Linux x64, glibc 2.35 or later.
- `msync-language-0.7.0.vsix`: installable VS Code extension.
- `SHA256SUMS`: checksums covering all four assets.

Historical release tags and asset bytes are unchanged.

## Verification

Implementation and package acceptance results are recorded in the
[integration workboard](../design/integration-v070.md). Local real-process
journeys are primary; platform packaging and native Windows/editor workflows
supply additional installation evidence rather than a separate quality gate.

The supplied script and source-free object/IR journeys passed locally, including
runtime filesystem changes, endpoint Scope ranges and actual OpenSSH operations.
The optimized local Linux package passed installed-program and SSH acceptance;
single file transfers retained one client/authentication/remote exec. Artifacts
produced by the published v0.6.6 executable also ran successfully after relocation.
The actual VS Code 1.144 host passed all 13 source-navigation and language-service
phases. Formatting and strict changed-contract Clippy checks passed.
