# msync 0.8.1

## Typed HIR

Version 0.8.1 separates source semantics from bytecode generation through an
explicit typed high-level representation. Binding identities, fixed storage
constraints, value reads, captures, control flow and callable specialization
belong to semantic analysis. Stack slots, instruction selection and branch
offsets belong to bytecode lowering. The default compiler runs
`Analyze -> HirLowerer -> Optimizer`; it does not retain the former emission
frontend as a fallback.

The new Core-only `Msync.Hir` project owns immutable semantic tables, structural
nodes, source and allocation identities, persistence, printing and pure lowering.
`Msync.Compiler` owns lexical binding, type/flow analysis, specialization and
semantic queries. Optimization and Runtime still consume the existing typed
bytecode, and Native AOT still produces one native executable.

Generic bodies are bound once. Recursive signature inference and semantic
queries use their own substitution/fact workspaces, without speculative
bytecode generation or later instruction repair. Deferred reads distinguish the
fixed storage domain from the current control-flow refinement. Code sharing does
not merge captured locations, anonymous objects or named singleton identities.

## Semantic files

```text
msync compile sync.msync --emit hir -o sync.mhir
msync disassemble sync.mhir --json
msync compile sync.mhir -o sync.mso
msync bind-ir sync.mso -o sync.mexe
msync run-ir sync.mexe
```

The new `.mhir` container uses format 1. A self-contained exported program can
be inspected, rewritten and lowered after its original source is deleted. Its
source text is optional diagnostic data, not syntax for the lowerer to replay.
Unresolved session locations are explicit imports; live cells, processes and
credentials are not serialized. Viewing HIR does not bind execution context or
authenticate remote endpoints.

VS Code opens `.mhir` as read-only semantic IR, with highlighting, definitions,
source references and file replacement/error recovery. Source completion,
hover and navigation consume the semantic model rather than generating
bytecode. The REPL retains transactional generations and a separate backend
layout for exported locations and runtime feedback.

## Compatibility and installation

The product version is 0.8.1. Existing `.mso` and `.mexe` files retain format 4
and language-semantic version 0.8.0. The source language, standard-library APIs,
default O2 policy, runtime resource ownership and native operation identities
are unchanged. Standard-library source URIs remain tied to that language bundle,
not mechanically renamed to the package version.

Install the complete Native package and the matching
`msync-language-0.8.1.vsix`, then reload VS Code and restart its language server.
The portable executable needs no installed .NET runtime. `SHA256SUMS` covers
the Linux archive, Windows portable archive, Windows installer and VSIX.
