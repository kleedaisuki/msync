# msync 0.8.5

## Contextual execution and object locality

The backend now prepares selected I/O as resource-versioned execution graphs:
known control flow and paths, finite transfers, directory expansion, dead
overwritten writes and safe copy forwarding are handled before execution.
Unprepared continuations resume after their actual inputs become available.
The VM schedules and executes recorded work; it does not revalidate complete
plans, detect filesystem staleness or automatically retry failed operations.

Numeric Scope payloads can share shape/allocation-site pages, while managed
references remain owned by individual objects. Object identity, aliasing,
captured locations, logical member order and fixed storage types are preserved.
Proved eager scans can fuse without changing each reduction's IEEE operation
order. Memory analysis runs after early fusion where possible, and backward
liveness uses successor-first work ordering.

## Power-user latency and correctness

This release removes empty contextual preparation and repeated whole-caller
rewriting for exact calls that need no preparation. Code emission avoids
per-instruction temporary arrays. Predicate analysis realizes alias invalidation
on demand instead of eagerly creating quadratic identity tables.

Persistent REPL facts use structurally shared roots rather than a growing chain
of past submissions. Binding descriptions project accepted exports and semantic
types instead of compiling an empty submission. Published facts retain exact
assigned identities, signed zero and NaN payloads. Colors, lexical highlighting
and hints remain enabled in the measured terminal experience.

Selected filesystem observations now pass dependency admission in namespace,
exact-entry and current-referent order. A pending observation resumes at its
execution frontier without replaying earlier effects, waiting for unrelated
jobs or serializing live tasks into artifacts. Process-flow deferral and finite
transfer admission retain their execution semantics.

Frozen Linux Native comparisons of this implementation report:

| Workload | Previous P99 | Changed P99 |
| --- | ---: | ---: |
| 8,192-row reference scan, executable IR | 147.98 ms | 100.68 ms |
| 8,192-row distinct-filename manifest, executable IR | 1,349.37 ms | 354.14 ms |
| Colored fixed-binding REPL, 1,024 requests | 63.07 ms | 14.22 ms |
| Colored growing REPL, requests 769–1,024 | 753.50 ms | 117.00 ms |

These are retained pre-release candidate measurements, not a new timing run of
the versioned packages. CLI and final session results use separately identified
Native producers. The manifest has 200 pairs and the growing REPL tail window
has 256 observations; those empirical percentiles are not population latency
guarantees. Light startup P99 did not establish a stable improvement. The
[measurement record](../design/performance-tail-v081.md) retains raw data,
sample/window limits, allocation and publication trade-offs, and remaining
optimizer costs.

## Compatibility and installation

- Product and VS Code extension version: **0.8.5**.
- Source language and embedded standard-library URI version: **0.8.0**.
- `.mso` and `.mexe` bytecode format: **5**; `.mhir` format: **1**.
- The earlier public 0.8.1 packages used bytecode format 4. Recompile their
  bytecode from source with 0.8.5; older formats are rejected rather than
  interpreted through a compatibility executable. Existing `.mhir` format-1
  files retain their semantic format.

Install the complete Linux or Windows Native package and matching
`msync-language-0.8.5.vsix`, then restart the language server. Native packages
need no installed .NET runtime. The release provides a Linux archive, Windows
portable archive, Windows installer and VSIX; `SHA256SUMS` covers all four.
Historical releases and their asset bytes remain unchanged.

One separately diagnosed existing Unix limitation remains: literal/stream
publication onto a dangling symbolic link can fail while inheriting the absent
referent's permissions. It is recorded in the tail investigation and is not
presented as an observation-admission fix or a successful transfer case.
