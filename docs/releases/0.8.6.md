# msync 0.8.6

## Collections, iteration and reflection

Construct empty typed collections directly: `$std::containers::Set::new(Number)`
does not insert a sentinel value. Seeded constructors still accept Ranges; Map,
BTree and BPlusTree expose `of_types(Key, Value)` without changing the meaning
of their existing prototype constructors. Types remain closed; these are library
operations, not new type syntax.

Keep `for` and lazy Range adapters for streaming input. A `Cursor` gives explicit
positions over a finite snapshot, with forward/backward movement, seeking,
cloning and binary bounds. A Null element is distinct from exhaustion. Sorted
merge and multiset algorithms stream their inputs and accept comparison policies.

`$std::meta::signature_of` describes a declaration; `try_invoke_result` infers
a concrete invocation once and returns `null` for an ill-formed call.
`members_of` distinguishes flow type from fixed storage type, and
`common_type_of` joins static Type witnesses. Reflection does not execute
inspected expressions. `msync skill library containers Set new` goes directly
to the embedded declaration instead of printing the entire module.

## Format text and use standard streams

```msync
$std::io::println($std::text::format("{}: {:.2f}", "Total", 12.5));
```

`format` supports brace placeholders, positions, escapes, alignment, precision
and numeric bases; `format_fields` selects named fields from a Scope. Formatting
is invariant and does not enumerate a lazy Range or wait on a Process merely
to display it. Literal checks and runtime formatting share their grammar.

Standard input offers `read_line`, `read_stdin` and the one-pass `stdin_lines`.
EOF is Null, not an empty String. `print`/`println` and `eprint`/`eprintln` write
raw text to separate streams; flush operations and `prompt` handle interactive
use. These operations use the execution's own reader/writers, not the language
server's framed streams. `msync skill library console` supplies a runnable
pipe → typed Set → formatted output example.

## Connections and the editor

Source now uses **`Connection @ Path`** (or a String on the right), for example
`remote @ ./config`. The left operand selects the real endpoint for completion;
opening a document or hovering a Connection does not start authentication. The
old source order reports a migration diagnostic.

The VS Code inspector gives `.mhir`, `.mso`, and `.mexe` stage labels, a grouped
outline, whole-artifact search, paged code, selected-line details and execution
plan links. The original read-only text view remains available; inspecting an
artifact never executes it.

Editor work is owned by document generations. Superseded work is cancelled,
presentation is produced on demand, and proven reusable lexical/semantic
prefixes survive edits without carrying stale definitions into a changed scope.
Named Scope self references use the declaration's type role even inside an
uncalled function; a shadowing anonymous Scope remains a variable.

## Compatibility

- Product and VS Code extension version: **0.8.6**.
- Artifact language semantics and standard-library URI version: **0.8.0**.
- `.mso` and `.mexe` use bytecode format **5**. Existing format-5 artifacts
  preserve their previous operand evaluation order.
- `.mhir` stays at format **1**. New connection-first expressions use an
  appended node tag: 0.8.6 reads existing HIR, but a 0.8.5 reader rejects that
  new node. Lower to format-5 bytecode for older runtime readers.
- The Unix dangling-link publication limitation documented for
  [0.8.5](./0.8.5.md) remains separate from these changes.

Use the complete Native package and matching `msync-language-0.8.6.vsix`.
See [standard-library contracts](../design/stdlib-v080.md),
[Range algorithms and cursor contracts](../design/ranges-v080.md), and
[semantic editor state](../design/editor-semantic-context-v080.md).
