# msync 0.9.3

## Save a program with one command

```sh
msync compile sync.msync            # writes sync.mso beside the input
msync compile sync.msync --prepare  # writes sync.mexe directly
msync run sync.mso                  # or run sync.mexe / sync.msync
```

The portable artifact pays compilation cost up front and selects work in the
environment it runs in. Preparing also pays contextual preparation cost up
front and can freeze already resolved file selections, without executing
transfer writes. No intermediate object is needed. Artifact formats have not
changed. Use `disassemble` to inspect an artifact, `--emit hir` to export typed
HIR, and `-o -` for binary stdout without a status message.

## Faster directory-tree transfers

- SSH upload can publish an absent destination root with one no-clobber rename
  when the receiver supports the operation. Merges use fewer remote helper
  processes and retain receiver-owned files.
- Linux local copies and SSH downloads overlap up to four staged small-file
  flushes while retaining ordered, atomic per-file publication and isolated
  failure cleanup.
- Windows retains native `CopyFileExW`, including native file attributes and
  streams. Diagnostics distinguish native copying, flushing and publication.

In the [Windows-to-Linux two-host benchmark](../benchmarks/windows-tree-io.md),
the 377-file tree's median fell from 4.62 to 2.68 seconds on first upload and
from 4.69 to 3.71 seconds on redeploy. These are measurements of that route,
not throughput promises for other links. See also the
[Linux I/O results](../benchmarks/0.9.2-io-attribution.md).
