# msync 0.9.5

## One physical execution format

Source runs, the REPL, and saved programs now use HPIR. Its instructions
operate directly on primitive data and addresses in a VM-owned stack and
heap. Concrete layouts, fixed call targets, closure captures, and typed
completion state reach execution without passing through the old generic
value model. Binding selects environment-dependent work without writing
transfer destinations or rerunning source optimization.

The command-line workflow is unchanged. Recompile older `.mso` and `.mexe`
files from source (or from a compatible format-4 `.mhir`); they are not
silently converted or executed. New portable and bound artifacts use
HPIR format 8:

```sh
msync compile sync.msync
msync compile sync.msync --prepare
msync disassemble sync.mexe
msync run sync.mexe
```

Quoted transfer destinations still resolve as paths; a String on the source
side still writes literal bytes. The CLI disassembler and VS Code artifact
view show escaped text literals without requiring the original source.

## Named Scopes as block results

A named Scope at the end of a block now yields its shared instance when there
is no trailing semicolon. For example, `fn get_pool { scope Pool { id: 1 } }`
lets callers read `get_pool()::id` without a separate `Pool` expression.
Initialization still happens once and repeated calls share mutations. If the
block should only declare the Scope and return Null, keep an explicit
semicolon after the inner declaration. The formatter preserves this distinction.

## Performance

On six matched Linux x64 workloads, the installed 0.9.5 binary used
70–96% less CPU time than published 0.9.3 at the median paired ratio.
Both binaries generated and bound their own artifacts and produced
identical output. See [workloads and measurements](../benchmarks/hpir-v095-default.md);
the reductions are workload results, not general I/O speed promises.
