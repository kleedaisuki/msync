# msync 0.9.6

## Object syntax

Replace `scope Name { ... }` and `scope { ... }` with
`object Name { ... }` and `object { ... }`. Replace the builtin type
`Scope` with `Object` and the reflection predicate
`$std::meta::is_scope` with `$std::meta::is_object`. The old spellings
are not aliases. Rename bindings that collide with the new spellings.
`$std::meta::type_name(Object)` returns `Object`.

```msync
object Counter {
    new: fn { object { value: 0 } },
};
let counter: Object = Counter::new();
counter::value = 1;
```

A named object still initializes once and shares its instance; an
anonymous constructor still allocates a fresh instance on evaluation.
Member selection, field mutation, captures, and alias identity are unchanged.
The editor, formatter, REPL, and embedded standard sources use the new
spellings. HIR remains format 4 and HPIR remains format 8. Use the new runtime
for artifacts compiled with the directory-creation service below.

## Recursive directory creation

`$std::fs::create_directories` works in source and compiled HPIR. It waits
for conflicting pending filesystem work, returns `false` if the directory
already exists, and preserves the failing path, source excerpt, and host
cause. Dry-run does not create directories. The packaged standard-library
smoke now exercises this path and checks its resulting file bytes.

## Compiler and REPL workflows

- Inspect compiler stages and save or resume an LLVM checkpoint. See
  [compiler stages and checkpoints](../design/compiler-stage-checkpoints.md).
- The REPL separates displaying a pending result from retaining it across
  submissions. Transfer and cleanup failures retain their original source
  and cause.
