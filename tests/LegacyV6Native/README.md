# Format-6 native import journeys

Run `dotnet run --project tests/LegacyV6Native` from the repository root.
The fixtures are frozen format-6 bytes generated by the retained 0.8.6 Native AOT
CLI, not artifacts regenerated by the implementation under test. Their adjacent
source files document provenance and intent; execution does not read them.
Each fixture is parsed as closed portable data, imported to native IR, validated,
written/read as a detached native artifact, and executed with exact stdout checks.

- `aliases`: independent mutable counter environments, captures extracted by
  legacy inlining, aliasing namespace fields and nested namespace projection.
- `builtins`: named statics, callbacks, finite ranges, type tests, regex records,
  zipped/enumerated host records and captured path spelling.
- `storage`: vector growth/shifts, copied snapshots and ownership-moving take,
  Scope element aliases, slot free-list/reset, arena links/release/clear.
- `heap` / `bplus`: real source collection algorithms with bounded fixture sizes.
- `higher-order`: returned closures and nested callback specialization.
- `mixed-fields`: captured places and direct host fields sharing the same name,
  including logical `member_type` / `members_of` reflection.
- `types`: historical Storage Type metadata (not a Storage runtime value), exact
  old alternatives omission, value type tests, private-header reflection and
  callable applicability.

Closed-data properties additionally verify constant-pool namespace
identity, equality of plain function references with null environments, and
historical allocator callable reflection after native serialization. A shared
historical binding bundle also executes vector, arena and slot adapters through
ordinary native calls, checking typed Scope aliases and logical Type descriptors.
It contains no retired native call or Storage execution type.

For the full CLI journey, supply the frozen prior executable explicitly:

```text
python3 tests/LegacyV6Native/cli_journey.py --frozen-cli PATH_TO_0.8.6_MSYNC
```

This compiles/binds with the prior product, deletes source, imports/rebinds and
executes both old and new artifact stages, verifies exact binary copy bytes,
checks file/stdin disassembly and rejects old format 5.

Pass explicit `.mso` / `.mexe` paths to exercise external frozen fixtures. A
sibling `stdin.utf8` supplies input and `expected.utf8` supplies expected stdout
when a per-fixture `.expected` file does not exist. `--validate` checks import and
native serialization without executing effects. It is not end-to-end evidence.

## Import invariants

The importer has no old VM, AST, HIR or source-replay dependency. The fixed point
tracks operand stacks, local types, callable identities and iterator lifetimes.
Control-flow edges copy to destination registers before jumping, including split
conditional edges; this is the usual edge semantics of
[SSA phi values](https://llvm.org/docs/LangRef.html#phi-instruction), without
requiring the destination IR itself to be SSA. Type-preserving lower-level
translation is also the organizing principle of
[typed assembly language](https://dash.harvard.edu/entities/publication/73120378-7eea-6bd4-e053-0100007fdf3b).

Only legacy namespace fields actually constructed from capture locations use
ordinary typed pointer fields plus independently owned payload allocations.
Mixed projections use ordinary finite `HasLayout` branches and typed field
addresses, so direct host fields and captured-place fields retain their own
invariant storage contracts. Plain fields remain direct typed fields. Constant-pool recipes
are initialized into hidden ordinary native statics once per interpreter, so
repeated reads retain the original allocation identity.

## Migration evidence and remaining work (2026-11-12)

The frozen `signal-hysteresis` corpus artifact executed natively with input
`65536\n17\n`, producing the exact expected six-line output:
`1588`, `151892`, `1024`, `900414`, `1024`, `457667`.
All thirteen frozen corpus `.mso` / `.mexe` pairs imported, validated and
round-tripped through native serialization (26 original artifacts). The full
frozen Heap scheduler also executed with its original 4096-request code and
seed 6, matching the prior product's complete stdout. The full BPlus inventory
reached the harness's three-minute guard; its bounded fixture executes both
artifact stages correctly. These are correctness receipts, not speed claims.

The real pending-process ingestion experiment uses a child waiting for a file:
source stores `child::exit_code` into `vector_new`, writes the file, then reads the
stored Number. The unchanged prior artifact completes with stdout `7` in the
native VM, proving ingestion does not join the future before the unblock effect.
A matching `ranges.materialize` journey now completes before releasing the child.
The maintained differential runner also freezes O0/O2 programs that copy one
pending value or create separate projections/computations: copied identity yields
one unique member, while distinct projections and binary computations yield two.

```text
python3 tests/LegacyV6Native/pending_journey.py --frozen-cli PATH_TO_0.8.6_MSYNC --native-cli PATH_TO_CURRENT_MSYNC
```

Each case uses fresh gated child directories and deletes its source before old
and native execution. Receipts retain the frozen artifact hash, exact stdout and
the original source as non-executable provenance under a unique root `.temp`
directory. A timeout releases only that case's child before reporting premature
payload demand. The dynamic Type-test case additionally checks that inspecting
an unresolved Number's result contract does not wait for its Process payload.

CLI format-6 input now goes exclusively through closed import and the native VM;
there is no source replay or old interpreter route. Historical allocator
signatures are private import data, not registered source/runtime capabilities.
The current frozen corpus is eleven `.mso`/`.mexe` fixture pairs plus four closed
native properties (26 journeys). Format-6 input and native output both execute
without source. Additional historical HIR-format-3 compatibility uses the same
ordinary typed-memory emitter through `NativeHistoricalBindings`, not an old
bytecode compiler or runtime.
